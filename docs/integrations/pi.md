# Pi 本机接入

使用已安装的 Pi 0.85.1 和 Cynosure 项目已有依赖。无需新增依赖、训练或准备种子数据。扩展通过同一个 `MOB_AI_API_KEY` 调用 Mob AI Router 上的候选模型、Jina 和 Jev，不运行本地 HTTP 代理。

在 Cynosure 目录运行：

```sh
npm run build
node --env-file-if-exists=.env scripts/pi.mjs /absolute/path/to/code-copy
```

脚本使用独立的 Pi 配置目录，显式加载扩展，不修改全局 Pi 配置。Pi 使用 `cynosure/auto`；同一代码目录持续复用经验。普通交互保留项目自己的上下文说明。实验执行另有文件和命令隔离，不要把普通交互入口误认为沙箱。

`CYNOSURE_DB` 可指定数据库，`CYNOSURE_SCOPE` 指定允许检索的项目范围，`CYNOSURE_CONFIG` 指定提供商配置。不设置经验文件时创建空库。`CYNOSURE_REQUEST_BUDGET_MICRO_USD` 是单轮调用预算，默认 10 美元；不是模型质量参数。输出默认 262144，GLM 两个模型按实际能力使用 131072。

## 实际反馈

每个模型轮次保存当前任务、近期宿主上下文、候选提案、选择证据和所有调用费用。Pi 执行选中的工具后，`tool_result` 回传工具名、参数、错误状态和结果。下一轮会检索到更新后的记录；用户后续输入同样作为可能的纠正保存。`/cynosure-feedback 具体反馈` 可补充用户验收，不把自然语言反馈机械转成成功分数。

`agent_end` 只记录运行结束，不等于用户验收。外部回归检查可通过 `Store.feedback` 追加有来源的任务级结果。多模型轨迹的最终结果属于整个轨迹，不能给每个参与模型都记一次独立成功。没有执行的候选工具没有运行成绩。

Jev 在每轮决定激活哪个候选、是否比较更多候选以及何时将提案交给 Pi。实际工具结果用于改变下一轮选择；不把“代码还没执行”作为拒绝交付工具动作的理由。提供商故障、费用、参数校验和预算由代码处理。零历史记录是正常状态。

## 实验边界

`scripts/live-coding/` 是本次四个历史缺陷实验的专用工具，不随 npm 包发布。复现需要对应源码及历史提交，并将脚本中的本机项目、Pi 和 Vitest 路径改为本地安装位置。

`scripts/live-coding/` 用历史缺陷的源码副本做外部检查。先按源码白名单选择 Git 文件，再导出，不复制素材、依赖目录、环境文件、数据库、构建缓存或原 Git 历史。现有 Node、Pi 和 Vitest 以原路径只读调用。候选模型修改自己的副本；命令不带凭据、禁止网络访问，文件内容默认不可读取，仅允许当前副本、检查器及必需运行库。临时目录、其他副本与 `/System/Volumes/Data` 别名中的原源码同样不可读，检查文件不可修改。

实验的 `runtime.json` 首次生成后固定，恢复不覆盖配置。`preflight.mjs` 使用相同沙箱验证旧版本失败、历史修复通过及越界访问被阻止。发现无效轨迹时保留原始日志、费用与 SQLite 备份，再从有效在线历史继续；排除记录不会成为后续路由的经验。

Cocos 检查使用轻量 `cc` 环境替身执行独立业务逻辑，不启动 Creator，不证明真机或 UI 行为。后端只测纯逻辑和 mock HTTP 的 Worker 测试，不启动服务或连接数据库。重复同一缺陷只能检验经验复用，不能证明新任务泛化或稳态；渠道错误与回归失败分别报告。
