# Cynosure：以 Jev 为决策核心的自适应模型路由

Cynosure 采用 **Jev-based Design**，将 Jev 的结构化判断放在模型路由的核心位置：由 Jev 在可执行动作中选择候选、追加比较和交付结果，代码负责预算与执行，经验检索和真实反馈持续提供判断依据。这一决策循环服务于 LLM 应用和 Coding Agent，无需训练专用路由模型。

当前版本：0.2.0 · Node.js / TypeScript · Apache-2.0。

## 本次评测使用的 Fusion 方案

文档中的 **Cynosure（Fusion）** 指由 **Grok 4.6、DeepSeek V4 Flash、GLM 5.3、GLM 5.3 Flash** 组成的生成候选池，Jev 负责路由与结果选择，embedding 模型负责经验检索。Fusion 可以按需尝试或比较候选，不要求每轮运行四个模型，也不涉及模型权重融合。四个单模型对照分别使用同一候选池中的一个模型。

候选可通过配置更换；效果数字对应本次固定池。完整[评测方法](validation.md)和[成本对比](benchmarks/costs.md)分别说明质量收益、调用开销与费用覆盖。

## 更多任务通过，更少重复开销

**参考 Aider 官方基准方法，本地通过率 85.4%，领先本次最佳单模型对照 14.6 个百分点。** 采用 [Aider Polyglot](https://github.com/Aider-AI/polyglot-benchmark/tree/7e0611e77b54e2dea774cdc0aa00cf9f7ed6144f) 官方题目与未修改的测试，按 [Aider benchmark](https://github.com/Aider-AI/aider/tree/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/benchmark) 的测试—修复流程运行 24 道 Python 题、每题两次。Cynosure 通过 41/48 次，最佳固定单模型 GLM 5.3 Flash 通过 34/48 次：通过率相对提升 **20.6%**，未通过次数从 14 次降至 7 次，**减少 50%**。

**Pi 四个真实缺陷，两轮目标回归检查 8/8 全部通过。** 同题重测继承实际在线经验，保持 4/4 通过，四题生成调用从 72 次降至 55 次，**减少 23.6%**；任务耗时之和从 1351.2 秒降至 733.9 秒，**减少 45.7%**。两轮共 7/8 次同时完成结尾交付，重测为 4/4。

这些是 Cynosure 本地运行的 Python 子集和 Pi 同题对照结果。完整对照、调用量与方法见[基准实测](validation.md)；大规模生产、未见任务泛化和长期成本收益待验证。

## 从第一条请求开始

Cynosure 可以从空经验库直接运行。候选模型通过已有 Router 接入，Jev 根据当前任务与可用证据选择执行动作，普通代码负责调度和预算。使用者无需先收集本业务的路由训练数据，也无需维护一张人工模型质量表。

随着任务进行，真实输出、工具执行结果、测试反馈和用户纠正逐步进入经验库。下一次相关请求到来时，Cynosure 检索这些案例，把可用经验交给决策模型。

## 围绕 Jev 构建决策循环

模型选择可以发生在任务开始时，也可以发生在看到结果之后。Cynosure 提供明确的动作集合：运行一个候选、比较剩余候选、交付已有结果或使用兜底模型。

这种方式允许应用根据新结果调整执行路径。Jev 做语义判断，生成模型产出答案或工具提案，代码维护执行状态与调用预算。每一步使用了什么证据、选择了什么动作，都可以在本地记录中查看。

## 把 Agent 的真实工具结果接回来

Pi 扩展将路由嵌入现有 Coding Agent。读文件、编辑代码和运行命令继续由 Pi 执行，Cynosure 只选择交给宿主的模型提案。

工具执行后的结果会成为反馈，用户的后续说明和纠正也可以追加到经验中。模型选择因此能看到实际工作过程，而不仅是最初的提示词。

适合从这些场景开始使用：

- 为现有 LLM 应用增加可配置的多模型执行与兜底。
- 在 Coding Agent 中接入模型选择和真实工具反馈。
- 比较候选模型在具体任务上的输出与执行结果。
- 研究经验检索如何影响后续模型选择。

## 轻量、可检查的实现

| 能力 | 实现方式 |
| --- | --- |
| 模型接入 | 复用 Router 的生成、embedding 与原生 Decisions 接口 |
| 语义判断 | Jev 从代码提供的有限动作中选择 |
| 经验检索 | 向量相似度与全文检索，通过 RRF 合并相关案例 |
| 持久化 | SQLite 保存任务、调用、结果、评价和反馈 |
| 调用预算 | 事务预留、费用来源区分与全调用记录 |
| Agent 工具 | 由 Pi 执行唯一选中的工具提案并返回观察 |

一个 Node.js 进程即可运行，唯一运行时依赖为 sqlite-vec。架构和数据合同见[架构说明](architecture.md)，相关技术来源见[开源生态](research/open-source.md)。

## 开始使用

从[快速开始](../README.zh-CN.md#快速开始)运行第一条请求，或通过 [Pi 扩展](integrations/pi.md)接入现有代码工作流。欢迎通过任务样例、反馈和代码贡献，一起扩展 Cynosure 的适用场景。
