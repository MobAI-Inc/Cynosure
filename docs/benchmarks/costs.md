# Fusion 成本对比与 OpenRouter 公开价重算

**目前不能确认 Fusion 综合成本更低。** 已公开的结果支持本次通过率提升，但逐次 token 用量尚未随仓库发布，不能仅凭调用次数完成按统一公开价的重算。本文先展示可从现有证据计算的费用小计，再固定 OpenRouter 参考价格与重算口径。

来源：[实验汇总](evidence.json)、[实验参数](../../eval/runtime.json)、[费用解析实现](../../src/providers.ts)。本页没有重新运行付费评测，也没有改动实验配置或历史结果。

## Python：现有账本小计

每组均为 24 题 × 2 次 = 48 次验证执行。`reported` 是渠道回报费用，`estimated` 是记录中的估算费用，`unknown` 是未定价调用。下面的小计是 `reportedUsd + estimatedUsd`，混合了不同计价来源，**不是按下方 OpenRouter 价格重算的总成本**。

| 执行方案 | 最终通过 | 报告费用（USD） | 估算费用（USD） | 已记录小计（USD） | 未定价 / 全部调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Cynosure（Fusion） | 41/48 | 0.560325 | 0.806610 | 1.366935 | 102/364 |
| GLM 5.3 Flash | 34/48 | 0.000000 | 0.142942 | 0.142942 | 7/73 |
| GLM 5.3 | 31/48 | 0.000000 | 1.902310 | 1.902310 | 11/67 |
| DeepSeek V4 Flash | 31/48 | 0.000000 | 0.310272 | 0.310272 | 10/71 |
| Grok 4.6 | 22/48 | 0.942852 | 0.029930 | 0.972782 | 25/53 |

Fusion 的 364 次调用由 142 次生成、159 次 Jev 决策、63 次 embedding 组成。它们全部属于该方案的运行范围，包括未被选中的候选和失败调用。其余四组的调用均为生成调用。未知费用不等于零；调用覆盖率也不是金额覆盖率。

| 执行方案 | 小计 / 验证执行（USD） | 小计 / 成功执行（USD） |
| --- | ---: | ---: |
| Cynosure（Fusion） | 0.028478 | 0.033340 |
| GLM 5.3 Flash | 0.002978 | 0.004204 |
| GLM 5.3 | 0.039631 | 0.061365 |
| DeepSeek V4 Flash | 0.006464 | 0.010009 |
| Grok 4.6 | 0.020266 | 0.044217 |

“小计 / 成功执行”将整组已记录费用（含失败尝试）除以成功次数，不是只统计成功任务的账单。所有均值均保留未定价缺口，也不包含学习批次的建库成本。Fusion 的小计高于 Flash 两组与 Grok 组、低于 GLM 5.3 组；这只描述已记录部分，不能据此排列完整总成本或宣称省钱。

记录中的小计下降 **26.1%**，但两轮都有未定价项，且覆盖范围不同，不能写成“总成本降低 26.1%”。[Pi 汇总脚本](../../scripts/live-coding/report.mjs)优先保留已有费用，仅对有 token 用量但没有费用的调用按实验价格补估；字段 `pricebookEstimateMicroUsd` 并不代表所有调用已按同一公开价格重算。重测复用了相同缺陷，另有渠道与协议变化，详见[实验范围](../validation.md)。

| 实验模型 | OpenRouter 参考 ID | 普通输入 | 缓存输入 | 输出 |

| Jina Embeddings v5 Text Small | 未找到匹配项 | 未知 | — | — |

四个生成模型取自 [OpenRouter Models API](https://openrouter.ai/api/v1/models)。DeepSeek 此 ID 对应 **V4 Flash 0423**；实验只记录了 Mob AI Router 的 `deepseek-v4-flash` 与目录日期，尚未确认底层版本，因此此行只能作为明确标注的 0423 参考情景，不能直接视作实验版本的真实报价。Grok 在输入达到 200,000 token 时有另一档价格，快照保留了 API 的分档字段。

Jev 价格取自 [OpenRouter 型号页](https://openrouter.ai/typesafe/jev-1.13)，本次通用模型目录未列出该型号；它是公开参考价，不证明 Mob AI Router 原生 Decisions 的实际计费一致。[OpenRouter Embeddings Models API](https://openrouter.ai/api/v1/embeddings/models)本次未列出匹配的 Jina 模型，其费用保留未知，不用其他供应商或其他 embedding 型号的价格替代。

公开价格会变化，也可能与实验渠道的折扣、版本和计费方式不同。因此重算结果应命名为 **OpenRouter 公开价 token 成本估算**，与原始账单并列，不覆盖历史账目。

## 拿到过程数据后如何重算

Python 的 `heldout-1.rows.jsonl`、`heldout-2.rows.jsonl` 中 `response.metadata.calls` 保存调用记录；各 trial 的 `experience.sqlite` 也有 `calls` 表。Pi 的在线经验库和各单模型 `baseline.sqlite` 同样保存调用记录。原始目录位置见[数据与复现](../validation.md#数据与复现)。公开汇总没有这些逐次用量，不能从费用小计倒推出各个模型的 token 数。

只需导出用于核算的调用 ID、任务/阶段、调用种类、实际模型版本、输入/输出 token、可用的缓存 token 和费用状态，无需发布提示词或私有源码。按固定公开价格对五组的同一批次逐次计算：

```text
单次估算 = (非缓存输入 tokens × 输入单价
          + 缓存输入 tokens × 缓存单价
          + 输出 tokens × 输出单价) / 1,000,000
方案 API 估算 = 全部生成调用 + Jev 决策调用 + embedding 调用
每次执行估算 = 方案 API 估算 / 执行次数
每次成功估算 = 方案 API 估算 / 通过次数
```

- 所有组使用同一价格快照。保留失败、修复、兜底和未选中候选的调用，不只统计最终答案。缺失用量或型号价格时单列未定价项。
- 缓存拆分缺失时可以另报“全部输入按非缓存价”的参考情景，不能假定存在缓存折扣。输出 token 按供应商记录的计费用量处理，避免重复加算已包含的推理 token。
- 冻结 seed 复制到 trial 的历史调用去重且不计为本轮新增开销。学习批次实际建库成本单列；需要端到端经济性时，再按明确的任务规模摊销。
- 公开价 token 估算不含本地测试算力、存储、人力或未记录的额外工具费，不能称为全部运营成本。账单成本与公开价估算分别汇总。

据此才能判断 Fusion 用多少额外或更少的成本换来了 7 次额外通过。若要证明调度本身的经济优势，还应增加单模型在相同预算和测试机会下的对照。
