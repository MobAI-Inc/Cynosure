# 本地基准实测

Cynosure 0.2.0｜2026-09-19｜Aider Polyglot Python 子集与 Pi 真实代码缺陷。

**官方代码测试通过率 85.4%，领先本次最佳单模型对照 14.6 个百分点，失败次数减少 50%。Pi 同题重测保持回归全部通过，任务耗时降低 45.7%，生成调用减少 23.6%。**

## Aider Polyglot：通过率 85.4%，失败次数减半

采用 [Aider Polyglot](https://github.com/Aider-AI/polyglot-benchmark/tree/7e0611e77b54e2dea774cdc0aa00cf9f7ed6144f) 官方代码题与未修改的 pytest 测试，参考 [Aider benchmark](https://github.com/Aider-AI/aider/tree/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/benchmark) 的“生成代码 → 测试 → 最多修复一次”流程，通过 promptfoo 0.123.1 在本地运行对照。24 道 Python 题，每题重复两次，每组共 48 次任务执行。

**Cynosure 以 41/48 次通过，取得本次五组对照中的最高通过率。** 相比最佳固定单模型 GLM 5.3 Flash 的 34/48：

- **通过率从 70.8% 提升至 85.4%**，提高 **14.6 个百分点**，相对提升 **20.6%**。
- **多通过 7 次任务执行**，未通过次数从 **14 次降至 7 次，减少 50%**。

| 执行方案 | 最终通过 | 通过率 | Cynosure 领先 | 生成调用 |
| --- | ---: | ---: | ---: | ---: |
| **Cynosure** | **41/48** | **85.4%** | — | 142 |
| GLM 5.3 Flash | 34/48 | 70.8% | **+14.6 个百分点** | 73 |
| GLM 5.3 | 31/48 | 64.6% | **+20.8 个百分点** | 67 |
| DeepSeek V4.1 Flash | 31/48 | 64.6% | **+20.8 个百分点** | 71 |
| Grok 4.6 | 22/48 | 45.8% | **+39.6 个百分点** | 53 |

Cynosure 首轮通过 31/48 次，包含一次修复机会后达到 41/48；46/48 次至少获得一份完整可送测代码。通过要求为交付代码通过该题全部官方测试。

### 评测方法

- **来源与执行：** 题目、测试和参考方法来自上述固定版本；结果由 Cynosure 本地运行 Router 适配流程产生，不是 Aider 官方榜单成绩。
- **题目与经验：** 另选 10 道不重合的种子题生成冻结经验。24 道验证题各自使用独立经验副本，同一任务修复可以读取自己的前一轮结果。
- **对照口径：** 各组使用相同任务提示、官方测试和最多一次修复机会。固定组始终使用一个指定模型，Cynosure 可以调用多个候选。结果衡量本次 Router 配置下的端到端任务通过率，渠道失败计入分母。
- **调用记录：** 上表列出全部生成调用；Cynosure 另有 159 次 Jev 决策和 63 次 embedding 调用。当前对照采用各自的执行策略，等调用量与等预算对照列入后续验证。

## Pi 真实缺陷修复：回归全部通过，重测耗时降低 45.7%

四个历史代码缺陷覆盖 Cocos 事件监听、请求重试，以及后端属性别名、OAuth 路径处理。使用 Pi 的实际读文件、编辑与命令工具修复源码，由外部回归检查验收产物。

**Cynosure 从零经验开始，首轮 4/4 通过；在全新缺陷副本上继承经验重测，再次 4/4 通过。两轮目标回归通过率达到 100%（8/8）。**

同题重测保持全部通过，四个任务耗时之和从 **22.5 分钟降至 12.2 分钟，降低 45.7%**；生成调用从 **72 次降至 55 次，减少 23.6%**。

| 指标 | 首轮四题 | 同题重测四题 | 变化 |
| --- | ---: | ---: | ---: |
| 目标回归通过 | 4/4 | **4/4** | **保持 100%** |
| 回归通过且完成结尾交付 | 3/4 | **4/4** | 增加 1 次 |
| 生成调用 | 72 | **55** | **减少 23.6%** |
| 工具调用 | 64 | 62 | 减少 3.1% |
| 四个任务墙钟耗时之和 | 1351.2 秒 | **733.9 秒** | **减少 45.7%** |

### 任务与统计口径

首轮连续执行四题并保存实际工具结果及外部检查反馈；重测使用相同任务、全新缺陷源码副本并继承在线经验。后续 Jev 决策已实际读取这些反馈。八次运行中，七次同时完成结尾交付，重测为 4/4。

Cocos 检查使用轻量 `cc` 环境替身，后端采用纯逻辑与 mock HTTP 测试；“通过”指固定的目标回归检查。耗时为四个任务各自墙钟耗时之和，生成调用单独计数，Jev 和 embedding 调用另行记录。

这些效率变化是同题重测实测值；实验期间包含渠道波动及协议适配调整，反馈的独立贡献待消融验证。全部五组记录、调用与费用覆盖见 [evidence.json](benchmarks/evidence.json)；排除轨迹保留原始证据，不计入上述正式成绩。
